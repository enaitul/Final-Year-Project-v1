AI-POWERED MYSQL AUTOMATED TESTING FRAMEWORK
CURRENT SYSTEM EXPLANATION

1. PURPOSE
This project executes and validates a 1,500-case MySQL test suite. It is a local Python-based multi-process test system. The word "agent" refers to an independent Python worker process; these are not LLM reasoning agents.

2. TEST SUITE
There are four CSV groups in test_cases/, each with 375 cases:
  group1.csv  TC001-TC375
  group2.csv  TC376-TC750
  group3.csv  TC751-TC1125
  group4.csv  TC1126-TC1500
The suite has 1,500 unique, contiguous Test_Case_ID values. Every row defines ID, feature metadata, type, preconditions, SQL, expected result/error, and risk level. Test types are Positive, Negative, and Edge.

3. WHY FOUR WORKERS
Four groups run concurrently to reduce elapsed time and avoid cross-group data conflicts. Each worker uses its own disposable MySQL database, ai_testing_group1 through ai_testing_group4, and produces its own response file and log.

4. EXECUTION FLOW
setup_group_databases.py drops and recreates the four disposable databases, grants the test account access, and creates the base schema.
orchestrator.py starts four test_runner.py processes in parallel and checks their exit codes.
test_runner.py performs setup SQL, executes test SQL, captures output/errors and elapsed time, then writes response_groupN.txt.
merge_and_validate.py sorts all records by Test_Case_ID, creates response_merged.txt and combined_group_test_cases.csv, then validates all 1,500 records.

5. PASS/FAIL AND VALIDATION
A positive test passes when its query succeeds. A negative test passes when its expected SQL error occurs. Edge tests are evaluated from expected result/error metadata. Validation checks required fields, ID format, test type, execution status, time format, duplicates, missing/unexpected IDs, and SQL consistency with the combined CSV. Failed executions are validation failures. A valid first run becomes the baseline; later runs are compared with it for regressions.

6. OUTPUTS
reports/agent_groupN.log              Per-worker logs
reports/response_groupN.txt           Per-worker labelled responses
reports/response_merged.txt           All 1,500 responses in ID order
reports/combined_group_test_cases.csv Combined validation source
reports/response_validation_report.txt Final validation verdict
reports/standard_test_results.txt     Regression baseline

7. RUN COMMANDS
From PowerShell in the project root, set credentials for the current session; never store passwords in source or documentation:
  $env:MYSQL_ADMIN_USER = "root"
  $env:MYSQL_ADMIN_PASSWORD = "<your-password>"
  python executor/setup_group_databases.py
  python executor/orchestrator.py
  python executor/merge_and_validate.py

The setup script deliberately removes only ai_testing_group1 through ai_testing_group4. Do not store important data in them.

8. VERIFIED RESULT
The latest complete run completed successfully: four workers exited with code 0, 1,500 records were merged, and validation reported 1,500 valid cases with zero invalid, duplicate, missing, or unexpected cases. Final verdict: PASS.

9. MENTOR QUESTIONS
Why local Python rather than cloud or an agent framework?
  The database and CSVs are local. Python subprocesses provide concurrency and isolation without cloud cost, deployment, or external dependencies.
How is isolation maintained?
  Each group uses a separate disposable database, separate fixtures, and separate response/log files.
What happens when a worker fails?
  The orchestrator reports failure. Inspect the matching agent_groupN.log, correct the issue, recreate the disposable databases, and rerun.
